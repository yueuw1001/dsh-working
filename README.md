# DSH Task Monitor

一个用于 [DeepSeek Harness](https://github.com/deepseek-ai) Web UI 的会话任务监控面板：入口在**左侧边栏**的面板图标里，点击后在中间打开看板。运行中的会话会自动收录；也可以手动添加「项目」，项目固定从「待运行」开始，不会被自动同步移动。

![status](https://img.shields.io/badge/DSH-Web%20plugin-2f6fed)

## 功能 / Features

- **左侧边栏入口**：与 插件 / 计划任务 / 行情雷达 等并列，点击图标在中央面板打开任务看板。
- **四状态看板**：待运行 / 运行中 / 已结束 / 未完成，四列并排展示，列头实时显示数量。
- **自动收录运行中的会话**：侧边栏里有会话开始运行时，自动生成一张「会话」卡片放进「运行中」，并开始计时。
- **按结束原因归档**：会话停止后自动分流——正常完成进入「已结束」；**运行出错或被中断（含手动停止）进入「未完成」**；两种情况都记录结束时间与用时。
- **每张会话卡片显示 token 用量**：累计总量（未缓存输入 + 输出 + 缓存读 + 缓存写），以 `1.2k tokens` 形式显示，悬停可看输入 / 输出 / 缓存读 / 缓存写明细。数据来自会话的 `tokenUsage` 投影，随运行实时更新；手动添加的项目不是会话，因此没有 token 行。
- **手动添加项目**：底部的「添加项目」输入框只把新项目放进「待运行」（卡片带「项目」标记）。这类项目不隶属任何会话，自动同步永远不会移动它，只有你自己拖动才会换列。
- **面板关闭也持续监控**：自动同步由一个常驻控制器驱动，看板没打开时同样会收录与归档，打开时状态已是最新。
- **卡片可拖动**：把卡片拖到另一列即可切换状态，同列内拖动可排序；拖动时有插入位置提示，支持列表边缘自动滚动。
- **手动接管**：把自动卡片拖到其它列后，该卡片由你接管，不再被自动移动；删除自动卡片后，该会话本次运行内不会再自动出现（下次运行会重新收录）。
- **整理现有卡片**：双击标题重命名、悬停删除、一键清理已结束。
- **持久化**：卡片与时间戳保存在浏览器 `localStorage`，刷新后仍在。
- **主题与语言**：全部样式使用 `--dsw-alias-*` 主题变量，随明暗主题切换；中英文随宿主语言切换。

> 两类卡片：带「会话」标记的由运行中的会话自动维护；带「项目」标记的是你手动添加的，始终从「待运行」开始、由你自行拖动。

## 打开方式 / How to open

- 安装并激活后，**左侧边栏**会出现「任务监控」面板图标（在插件 / 计划任务 / 行情雷达等图标旁）。
- 点击图标即可在中央面板打开看板；切换到其它面板不会停止后台同步。
- 之前版本注册的右侧栏标签页已停用，若它还开着，会显示一条「已移到左侧边栏」的提示与打开按钮，关闭即可。

## 安装 / Installation

插件以 DSH bundle 形式安装（推荐）：

1. 将本仓库放到任意目录。
2. 在 DSH 中安装该 bundle：

   ```text
   plugin_manager(install_bundle, target: "<本仓库绝对路径>")
   ```

3. 刷新一次 Web 页面，左侧图标即可出现。

也可以用 `pnpm add <path>` 将该包加入 profile 依赖，然后在 `cordis.patch.yml` 中插入同名行。

## 使用 / Usage

- 让一个会话跑起来：它会自动出现在「运行中」，卡片带「会话」标记、实时计时与累计 token 用量。
- 会话正常跑完 → 卡片进「已结束」；出错、手动停止或中断 → 卡片进「未完成」，都带耗时与 token 总量。
- 在底部输入项目名称并回车（或点「添加项目」）：新项目进入「待运行」，卡片带「项目」标记；不会被自动同步移动。
- 按住卡片拖动：拖到其它列 = 改变状态，拖到同列其它位置 = 排序。
- 双击卡片标题可重命名；悬停卡片右上角出现删除按钮。
- 底部右侧绿点表示自动同步可用，悬停有说明。

## 开发说明 / Development Notes

- `client.js` 是 DSH 动态 Client 模块格式：`window.__ModuleLoader__.load({ id, factory(require) { ... } })`，React 由浏览器模块表提供，无需安装依赖。
- 三个扩展点：
  - `sidebar.panellist`（id = `task-monitor`）提供左侧面板图标，侧边栏负责按钮与选中状态；
  - `main`（key = `task-monitor`）提供中央看板页；
  - `shell.overlay` 里的 `task-monitor-controller` 常驻运行，驱动模块级 store，因此看板关闭时也在同步。
- 自动同步数据源：槽位标准属性 `useSessions`（会话列表：`ids` / `byId`）与 `useSessionStatus`（每会话状态 Map：`running`）。
- 结束原因：`retain` 运行中的会话，读取其事件窗口里最后一个 `turn/end` 的 `reason.kind`。`completed` = 已结束，`error` / `aborted`（手动停止）/ `interrupted` / `max-tokens` / `blocked` 等 = 未完成；判定后立即释放。事件窗口不可用时回退为「已结束」。
- 样式只使用 `--dsw-alias-*` 主题变量；所有类名以 `tm-` 前缀限定，避免污染宿主页面。
- 数据保存在 `localStorage` 的 `dsh.task-monitor.board.v1`。

## 已知限制 / Known Limitations

- 任务数据保存在当前浏览器，不跨设备同步。
- 只按「侧边栏会话」收录；命令行/子代理等后台作业暂不单独建卡。
- 自动同步以会话结束事件为准；事件窗口不可用时会回退为「已结束」。
- 插件代码更新后需要刷新一次页面才会加载新的客户端模块。
